# Стратегии winws

В версии 0.3.2 раздел **«Стратегии»** позволяет выбрать способ обработки TLS-запросов встроенного WARP без редактирования конфигурации. Это варианты для WARP MASQUE через TCP 443, а не набор правил для всего браузерного или игрового трафика.

## Как пользоваться

1. Выберите свой сервер в верхнем списке. Для него должен быть включён встроенный WARP.
2. Откройте «Стратегии». Шесть встроенных вариантов доступны без загрузки. Базовый сохраняет поведение 0.3.1.
3. При необходимости нажмите **«Обновить с GitHub»**. Каталог можно обновлять при работающем мосте: это не применяет новые параметры.
4. Для проверки сначала выключите профиль AmneziaVPN, затем мост VPSLink. Остановите внешний winws/zapret и отключите системный WARP. Проверка откажется запускаться при обнаружении работающих winws/usque или активных Amnezia/WARP-адаптеров; сама их не останавливает. Доступ к интернету на время проверки может отсутствовать — не выполняйте её во время удалённого сеанса, который зависит от VPN.
5. Откройте раздел от администратора и нажмите **«Проверить выбранную»** либо **«Подобрать автоматически»**. Перебор идёт по порядку до первого подтверждённого пути, до 25 секунд на вариант. «Отменить проверку» останавливает только процессы, созданные проверкой.
6. После успеха нажмите **«Использовать для сервера»**, подключите VPSLink и включите прежний профиль AmneziaVPN. Проверьте интернет обычным способом. Подбор подтверждает соединение до VPS и ожидаемый SSH-ключ, но не VPN-рукопожатие, DNS, скорость или отсутствие утечек.

Если уже всё работает, менять стратегию необязательно. При неудаче можно выбрать **«Вернуть базовую»**. Кнопка **«Предыдущий каталог»** возвращает предыдущую локальную версию каталога; отдельно сохранённая стратегия сервера при этом не меняется. Автоматического переключения при каждом подключении нет.

Для первичного подбора требуется существующая регистрация WARP. Регистрация выполняется при первом обычном подключении, с подтверждением условий Cloudflare. Изменение стратегии не создаёт новую регистрацию и не переустанавливает драйвер.

## Источник и ограничения импорта

Источник закреплён в коде: [`bol-van/zapret-win-bundle`, `zapret-winws/preset1_example.cmd`](https://github.com/bol-van/zapret-win-bundle/blob/master/zapret-winws/preset1_example.cmd). Это официальный пример legacy winws; winws2/Lua и сторонние наборы BAT не поддерживаются. Число импортированных вариантов зависит от текущего содержимого примера. Обновляется **каталог параметров**, а не исполняемый файл winws, WinDivert или usque.

Клиент сначала получает SHA коммита ветки `master`, затем читает файл именно из этого коммита через GitHub API по HTTPS. Проверяются путь, тип, размер, кодировка и Git blob SHA-1. Это контроль соответствия ответу GitHub, не независимая подпись автора. Перенаправления на другие адреса не принимаются; токен GitHub не нужен. Компрометация исходного репозитория остаётся риском, ограниченным разрешёнными параметрами.

Скачанный CMD **никогда не исполняется**. Импортёр извлекает только секции TCP 443 и допускает ограниченный перечень `--dpi-desync*` с ограниченными значениями. Параметры захвата, `--new`, пути к файлам, Lua и неизвестные параметры не передаются процессу. Секция с неподдерживаемыми параметрами пропускается целиком. Исходные списки сайтов отбрасываются: параметры адаптируются к единственному IPv4-адресу MASQUE из локальной регистрации WARP.

Фильтр захвата остаётся заданным VPSLink: исходящий IPv4 TCP, порт назначения 443, точный IP MASQUE. Параметры передаются через `ProcessStartInfo.ArgumentList`, без командной оболочки. SHA-256 исполняемых компонентов проверяется прежним механизмом приложения.

## Хранение и проверка

`winws-catalog.json` и предыдущий `winws-catalog.json.bak` хранятся рядом с профилями в `%LOCALAPPDATA%\ThingsNotFun-Link`. Сначала записывается и повторно проверяется временный файл, затем он атомарно заменяет каталог. Невалидный ответ или отсутствие совместимых секций сохраняют прежний каталог. При восстановлении повреждённый файл сохраняется отдельно, без затирания исправной резервной копии.

Профиль содержит собственный снимок выбранных параметров и версию источника. Загрузка нового каталога не меняет этот снимок и не перезапускает текущие процессы. Старые профили без нового поля используют базовую стратегию. Пароли, ключи и настройки ручного подключения при сохранении стратегии сохраняются.

Проверка использует только выбранную стратегию и встроенный WARP, а при настроенном HTTPS-шлюзе — этот шлюз поверх WARP. Другие транспортные пути не подставляются. SSH-пароль при проверке не используется, команды на VPS не выполняются; relay-токен применяется, если его требует настроенный шлюз. После каждого варианта собственные usque/winws завершаются. Для определения «лучшей по скорости» стратегии проверка не предназначена.

Автотесты покрывают ограничения импорта и фильтра, отказ при невалидном GitHub-ответе, сохранение профилей, откат, остановку перебора и отмену. Работоспособность конкретной стратегии зависит от провайдера и проверяется пользователем в его сети.
