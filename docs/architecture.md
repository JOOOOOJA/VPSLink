# Архитектура VPSLink

VPSLink — Windows Forms-приложение, локальный UDP-мост и мастер настройки клиента существующего AmneziaWG. Это не самостоятельный сетевой драйвер VPN. Адреса, маршруты и VPN-интерфейс устанавливает отдельная AmneziaVPN.

## Передача данных

1. AmneziaVPN отправляет зашифрованные датаграммы AmneziaWG на `127.0.0.1:<порт профиля>`.
2. VPSLink принимает их через UDP loopback, помещает в кадры собственного протокола (`Wire.cs`) и передаёт через стандартный ввод/вывод Windows OpenSSH.
3. Python relay выполняется на VPS в SSH-сеансе. Он отправляет датаграммы выбранному VPN endpoint и возвращает ответы тем же каналом.
4. AmneziaWG на VPS обрабатывает VPN-трафик. При корректной конфигурации выхода/NAT интернет видит адрес VPS.

Внешний канал SSH — TCP; внутри него остаются зашифрованные VPN-пакеты. При потере TCP-сегментов следующие пакеты ждут восстановления потока (head-of-line blocking). Большая задержка/потери могут ухудшать голос, игры и скорость; производительность не эквивалентна нативному UDP VPN.

### Разделение по приложениям

С 0.5.0 VPSLink поддерживает отдельный [прямой маршрут для приложений](direct-routing.md). Профиль выбирает Steam, точные пути к `.exe` и чтение сохранённого списка исключений AmneziaVPN. После подтверждения VPN sing-box принимает трафик из более конкретных IPv4-маршрутов и отправляет его через явно выбранный интерфейс провайдера или AmneziaVPN.

### Совместимость с нативными исключениями AmneziaVPN

По умолчанию UDP-мост слушает `127.0.0.1`. В AmneziaVPN интернет-интерфейс для драйвера исключений выбирается по маршруту до VPN endpoint; loopback endpoint может привести к выбору loopback вместо физического интерфейса. Это ломает новые внешние соединения исключённых приложений.

Необязательный `LocalUdpAdapterId` выбирает Ethernet/Wi-Fi по идентификатору. Мост слушает единственный рабочий IPv4 этого адаптера, принимает только пакеты с этого же адреса и экспортирует фактический адрес в VPN-профиль. Wildcard bind не используется. Недоступный или неоднозначный адаптер вызывает ошибку без молчаливого отката. После изменения IP нужен повторный экспорт/импорт профиля. Режим не меняет системные маршруты и брандмауэр.

Это **не полное исправление игрового split tunneling**: драйвер Mullvad, используемый AmneziaVPN, перенаправляет UDP bind исключённых приложений с `INADDR_ANY` на физический адрес. Неявно привязанный сокет теряет возможность отправлять на localhost. Ограничение описано в [документации драйвера](https://github.com/mullvad/win-split-tunnel#localhost-udp-communications) и [отчёте Amnezia о Deadlock](https://github.com/amnezia-vpn/amnezia-client/issues/1320). Исправление выбора интерфейса не устраняет это ограничение; успешного TCP probe недостаточно для подтверждения работоспособности игры.

UDP-сокеты Link запрашивают приёмный буфер 256 КиБ для коротких пачек пакетов; фактический размер на Linux ограничивается настройками ядра. Link не меняет системные лимиты. Это уменьшает потери при краткой задержке чтения, но не устраняет очереди и повторные передачи во внешнем TCP.

Для опубликованного loopback-порта единственного найденного контейнера relay повторно проверяет привязку порта и сети Docker. При наличии локального маршрута через bridge он отправляет UDP прямо на IP контейнера и внутренний порт, исключая промежуточный `docker-proxy`. При нескольких сетях используется явно настроенная основная сеть контейнера. Если определить путь однозначно не удалось, сохраняется опубликованный адрес. Пользовательские адреса вне loopback не заменяются. Маршрут не доказывает разрешение UDP нестандартным firewall; при такой конфигурации прямой путь необходимо проверить отдельно. Адрес назначения выводится в диагностике. Уже выданные приглашения используют свою установленную копию relay и автоматически от обновления Windows-клиента не меняются.

Диагностика отмечает запись пакета в SSH длительностью от 100 мс и ответы heartbeat от 250 мс, не чаще одного сообщения каждого вида за 10 секунд. Эти значения включают ожидание транспорта и планирование процессов, а не только сетевой RTT. Пакеты и ключи в эти сообщения не попадают.

## Пути до SSH

`Supervisor` выбирает разрешённые профилем транспорты: прямой TCP, активный адаптер WARP, SOCKS5, HTTP CONNECT, встроенный usque. HTTPS/WebSocket relay может оборачивать доступ к SSH через доступный HTTPS-hostname. Путь не считается пригодным только по имени адаптера: выполняется соединение и проверяется закреплённый ED25519-ключ SSH.

Для встроенного ядра:

- `usque.exe` 4.2.1 проверяется по закреплённому SHA-256.
- Оно запускается отдельным дочерним процессом в SOCKS-режиме, привязано к loopback и использует MASQUE/HTTP2 с SNI `www.cloudflare.com`.
- Адрес IPv4 MASQUE берётся из отдельной регистрации пользователя. Требуется маршрут к нему через физический Ethernet/Wi-Fi/подходящий мобильный адаптер.
- Экспорт VPN-профиля исключает этот адрес из IPv4 AllowedIPs, чтобы внешний транспорт не попал в собственный VPN.
- Окружение HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY очищается только для дочернего usque, чтобы избежать неявного цикла.

VPSLink запускает выбранный или комплектный `winws.exe`. Фильтр ограничен исходящим IPv4 TCP/443 к выбранному MASQUE endpoint. Базовые параметры: `--dpi-desync=multisplit --dpi-desync-split-pos=1`. С версии 0.3.2 можно сохранить другую стратегию для сервера и обновить ограниченный каталог из zapret; [механизм подбора и импорта](strategies.md). При явно выбранной небазовой стратегии работающий чужой winws/winws2 считается конфликтом. Старые профили в базовом режиме сохраняют возможность использовать уже работающий внешний winws. Применимость стратегии зависит от сети. Это не общий обход для всех приложений Windows. Собственные дочерние процессы прекращаются при остановке моста; чужой winws приложение не останавливает.

## HTTPS-шлюз

Windows → выбранный транспорт → HTTPS/WebSocket Cloudflare → cloudflared на VPS → loopback Python relay → SSH на VPS. Relay требует отдельный случайный bearer-токен, но это не замена SSH-аутентификации. TLS проверяется системными механизмами, SSH — закреплённым ключом сервера. Cloudflare терминирует внешний TLS и видит метаданные; SSH и AmneziaWG остаются внутренними защищёнными каналами.

Первоначальная установка шлюза требует уже работающего административного SSH-пути. Нельзя обещать настройку полностью недоступного VPS «из ничего». Точный состав файлов и служб — в [server-changes.md](server-changes.md).

## Профиль и диагностика

Мастер находит опубликованные UDP-порты и интерфейсы AmneziaWG, позволяет выбрать нужный VPN и создаёт отдельного peer или импортирует существующий `.conf`. Импорт не исполняет PreUp/PostUp и подобные команды. При сохранении меняется Endpoint на loopback; параметры AWG, в том числе AWG 3.x, сохраняются.

Статус готовности моста не означает готовность VPN. VPN подтверждается свежим рукопожатием, двусторонними UDP-пакетами и ростом счётчиков выбранного peer. Проверка интернета дополнительно выполняет HTTPS-запрос с привязкой к IPv4 VPN-интерфейса. Это проверка конкретного запроса, не универсальный тест всех приложений, DNS/IPv6-утечек или kill switch.

## Совместимость имени

Продукт переименован из ThingsNotFun Link в VPSLink. Сохранены идентификатор установщика, каталог пользовательских данных `ThingsNotFun-Link`, mutex, имена задач и существующих служб VPS. Это намеренные внутренние идентификаторы миграции: изменение имени не должно лишить пользователя старых профилей или создать второй шлюз. Свежая установка называется VPSLink; обновление использует ранее выбранный каталог установки.
