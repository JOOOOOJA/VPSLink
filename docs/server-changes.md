# Действия на VPS

## VPN

Требуются существующий AmneziaWG, SSH с правами выполнять нужные команды и Python 3.8+. VPSLink не устанавливает VPN на пустой сервер. Диагностика читает интерфейсы, маршруты, UDP listeners, сведения Docker и доступных `awg`/`wg`-интерфейсов. При неоднозначности пользователь выбирает VPN.

При создании клиента генерируется отдельная пара ключей, выбирается свободный адрес, добавляется peer в выбранный интерфейс и сохраняемую конфигурацию. Код проверки/изменения — `src/NetUlta/awg_setup.py`; тесты проверяют сохранение остальных peer и обработку ошибок. Для отдельных устройств используйте разные ключи. Административные права SSH нужно ограничивать с учётом конкретной установки; PoC не создаёт универсального ограниченного SSH-пользователя.

Обычный relay работает в SSH-сеансе и прекращается вместе с ним. Внешний дополнительный публичный UDP listener для моста не создаётся.

## Постоянный шлюз Cloudflare

В интерфейсе нужны свой аккаунт Cloudflare, активная зона, свободный поддомен и API-токен:

- Account / Cloudflare Tunnel / Edit;
- Zone / DNS / Edit;
- Zone / Zone / Read.

Область токена ограничьте своим аккаунтом и выбранной зоной. Токен управления API используется в процессе настройки, не включается в профили/релиз. Отдельный токен подключения cloudflared хранится на VPS; отдельный токен relay защищается локально DPAPI.

На Linux x64 с systemd мастер создаёт:

| Путь или служба | Назначение |
|---|---|
| `/opt/thingsnotfun-link-gateway` | Python relay и проверенный cloudflared |
| `/etc/thingsnotfun-link-gateway` | Приватная конфигурация и токены с ограниченными правами |
| `thingsnotfun-link-relay.service` | Relay на `127.0.0.1:18093`, доступ к локальному SSH |
| `thingsnotfun-link-cloudflared.service` | Исходящий Cloudflare Tunnel через HTTP/2 |

Cloudflared 2026.11.0 скачивается с официального GitHub и проверяется по закреплённому SHA-256. Службы включаются в автозапуск VPS и восстанавливаются после сбоя. Это **серверный** автозапуск; Windows-клиент по умолчанию запускается вручную.

В аккаунте Cloudflare создаются именованный туннель и проксируемая CNAME-запись поддомена. Занятая чужая DNS-запись не заменяется. Повторный запуск использует идентификаторы из сохранённого профиля. Прежний адрес профиля заменяется только после проверки нового канала. Мастер не меняет основной SSH-порт, настройки nginx или NS домена. Отдельный старый инструмент `tools/https-relay/install.py` для nginx — альтернативный ручной путь; он не запускается мастером автоматически.

## Резервирование и удаление

До настройки сохраните конфигурацию VPN и доступ к консоли хостера. Не удаляйте общий VPN-контейнер ради удаления VPSLink. Для удаления серверного шлюза сначала остановите только две указанные службы, проверьте, что ими не пользуются другие клиенты, затем удалите соответствующие конфигурации и записи Cloudflare. В PoC нет кнопки безопасного удаления всех серверных ресурсов: их нужно проверить вручную.

Имена служб сохранены для совместимости с ранними локальными версиями. В исходниках и релизе нет общего VPS, домена или токена проекта.
